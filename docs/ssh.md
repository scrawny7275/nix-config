# SSH Configuration for Multiple Identities (NixOS + Home Manager)

SSH authentication succeeds because sops-nix materializes private keys outside the Nix store and Home Manager wires them via explicit host aliases; the ssh-agent currently mediates key usage, so agentless verification is required to guarantee deterministic behavior.

## Goal

The goal is to scale SSH identity management cleanly across:

- Multiple GitHub accounts
- Multiple machines (laptop, workstation, server)
- A single user managed by Home Manager
  This is achieved by:
- Using SSH Host aliases to bind identities to repositories
- Using Home Manager modules to scope configuration per machine
- Splitting configuration into shared defaults + host-specific overrides

## SSH Host Aliases (Conceptual View)

The resulting ~/.ssh/config (generated by Home Manager) looks like:

```text
# GitHub account: <account-a>
Host github.com-youruser
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519_personal
  AddKeysToAgent yes
  IdentitiesOnly yes

# GitHub account: <account-b>
Host github.com-yourseconduser
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519_secondary
  AddKeysToAgent yes
  IdentitiesOnly yes
```

### Key points

- Host: Alias used for SSH host
- HostName: This tells SSH where to connect (in this case, github.com).
- IdentityFile: Path to the corresponding private key
- AddKeysToAgent: Automatically load key to the SSH agent
- IdentitiesOnly: Ensures only the specified identity is used when connecting, preventing SSH from trying unrelated keys in the agent

## Architectural Approach

The configuration is split into:

- Shared SSH defaults (applies everywhere)
- Host-specific identity definitions (per machine)

Here’s how to configure it with Home Manager:

### Shared SSH module

File: [modules/user/security/ssh.nix]

```nix
services.ssh-agent.enable = true;  # Ensures the SSH agent runs

programs.ssh = {
  enable = true;  # Enable the SSH client configuration
  enableDefaultConfig = false;  # Prevents the default SSH config from being included
}
```

Purpose:

- Enable SSH client
- Ensure agent is running
- Avoid implicit default SSH behavior

This file should never contain identities.

### Host-specific modules

File: _hosts/<host_name>/ssh.nix_

```nix
{
  programs.ssh.settings = {
    "github.com-youruser" = {
      host = "github.com-youruser";
      hostname = "github.com";
      user = "git";
      identityFile = "~/.ssh/id_ed25519_personal";
      identitiesOnly = true;
      addKeysToAgent = "yes";
    };

    "github.com-yourseconduser" = {
      host = "github.com-yourseconduser";
      hostname = "github.com";
      user = "git";
      identityFile = "~/.ssh/id_ed25519_secondary";
      identitiesOnly = true;
      addKeysToAgent = "yes";
    };
  };
}
```

Purpose:

- Contains the host-specific identities or host aliases
- Allow machines to differ in available keys

**Explanation**:

- matchBlocks: This is where the host aliases are defined, mapping each alias (github.com-youruser, github.com-yourseconduser) to its respective SSH key.
- hostname: This is the actual GitHub domain that the aliases will point to.
- identityFile: The path to the specific private key for each account.
- identitiesOnly: Ensures only the specified identity is used, preventing SSH from defaulting to another key in the agent.

### Home Manager Import Wiring

File: _hosts/laptop/home.nix_

````nix
imports = [
  ../../modules/system/security/ssh.nix       # shared defaults
  ./ssh.nix                            # host-specific identities
];

This guarantees:

- Consistent defaults everywhere
- Machine-specific SSH identities

## Scaling: Adding a New GitHub Account

As your number of GitHub accounts (or other SSH-based services) grows, you can easily extend this setup. Here's how to handle future additions:

1. Create a new SSH key:
```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_newuser
```
2. Define new Host aliases in your matchBlocks configuration.
```nix
"github.com-newuser" = {
  host = "github.com-newuser";
  hostname = "github.com";
  user = "git";
  identityFile = "~/.ssh/id_ed25519_newuser";
  identitiesOnly = true;
  addKeysToAgent = "yes";
};
```

3. Update your Git remotes to use the new alias for the corresponding repository.

```bash
git remote set-url origin git@github.com-newuser:newuser/repo.git
```

## Scaling: Adding a New Machine

1. Create _hosts/<new_host>/ssh.nix_:

```nix
{
  programs.ssh = {
    matchBlocks = {
      "github.com-newuser" = {
        host = "github.com-newuser";
        hostname = "github.com";
        user = "git";
        identityFile = "~/.ssh/id_ed25519_newuser";
        identitiesOnly = true;
        addKeysToAgent = "yes";
      };
    };
  };
}
```

2. Import it in _hosts/<new_host>/home.nix_:

```nix
imports = [
  ../../modules/system/security/ssh.nix
  ./ssh.nix
];
```

3. Deploy:

```bash
home-manager switch --flake ~/nix-config#newhost --impure
```

## Test Each Identity

After making changes to the SSH config or adding new identities, you should test each identity to ensure the SSH agent is using the correct key.

Use the -T flag to test each alias:

```bash
ssh -T github.com-youruser
ssh -T github.com-yourseconduser
ssh -T github.com-newuser
```

Each should authenticate with the correct GitHub account, and the expected message should be displayed.

## Notes on Key Management

The SSH agent is responsible for storing and using the keys during your session. The services.ssh-agent.enable = true option in Home Manager ensures the agent is started and can be accessed by SSH.

You can add new keys to the agent manually by running ssh-add ~/.ssh/id_ed25519_newuser, or Home Manager will automatically manage this for you based on the configuration.

## Scaling Considerations

**Key Rotation**: You may need to rotate keys periodically. Ensure that all repositories and configurations that rely on these keys are updated accordingly.

**Automated Key Management**: You can automate key addition and removal via scripts or integration with CI/CD pipelines.

**Repository Management**: As you scale, consider organizing repositories into groups (e.g., github.com-work, github.com-personal) to avoid confusion and ensure smooth scaling.
````
